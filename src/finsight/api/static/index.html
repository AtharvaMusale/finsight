03 How it works

A graph of small steps, with code at the edges.

A LangGraph pipeline. Language-model steps are boxed in by code that retrieves, calculates and verifies.

  • Language model
  • Plain code
  • Search and data

  1. Plan rules + 1 cheap call

    Rules pull out tickers, years, form type and section hints. One small call decides whether the question needs numbers, an explanation, or both. A comparison becomes one sub-query per company and year.

  2. Retrieve hybrid search

    One dense plus sparse Pinecone search, narrowed by a metadata filter (ticker, year, form, section).

  3. Facts guarded SQL

    Text-to-SQL over a read-only view of the XBRL facts. The SQL must be one allowlisted SELECT. A calculator does growth and margins.

  4. Compose cited answer

    Writes the answer and labels each claim: [C#] filing text, [F#] a database row, [K#] a calculation.

  5. Verify three layers

    Code checks that every number appears in the evidence and every label exists. A critic must back each claim with a verbatim quote, and code confirms the quote is really in the cited text.

  6. Revise capped loop

    Problems go back to the writer, at most max_revisions times (default 1).

  7. Finalize caveat by code

    Anything still unsupported is marked with a caveat added by code, never by the model. The disclaimer is added here too.

Numbers never come from the model

They come from DuckDB rows or the calculator, and the verifier rejects any number that appears in no evidence.

Filings are untrusted text

Chunks are wrapped as data, so instructions hidden in a filing are never followed.

Tools are guarded

SQL is read-only and allowlisted. The calculator has named operations and no eval.

Agents distrust each other

A2A responses are schema-validated and size-capped, and a verifier outage fails closed with a caveat.

Local only

The API, MCP and A2A agents bind to 127.0.0.1. The A2A agents have no authentication, so do not expose them to a network.

PineconePassages for semantic search (hybrid dense + sparse).
DuckDBFilings, chunks and XBRL facts, opened read-only when answering.

04 Ways to use

Four ways in, one pipeline.

All of them run the same graph and leave a trace you can open above. Every command can be copied as written.

Set it up once

You need Python 3.11, uv, a free Pinecone account and an Anthropic API key.

  • FINSIGHT_SEC_USER_AGENT: the SEC requires a real contact, for example "MyApp you@example.com"
  • PINECONE_API_KEY and ANTHROPIC_API_KEY
  • Keys live only in .env, which is gitignored.
1 · install
git clone git@github.com:AtharvaMusale/finsight.git
cd finsight
cp .env.example .env     # then add your keys
uv sync
2 · ingest the filings (once, safe to repeat)
uv run python -m finsight.ingestion.pipeline
3 · start the server and open this page
uv run uvicorn finsight.api.app:app --host 127.0.0.1 --port 8000

HTTP API

Best for scripts and UIs. This page is a client of it. FastAPI also serves an interactive page at /docs where you can try each endpoint.

Every response carries an X-Trace-Id header and a trace_id field, so one request can be followed everywhere.

ask a question
curl -s localhost:8000/ask -H 'content-type: application/json' \
  -d '{"question": "What drove growth in Azure and other cloud services at Microsoft in fiscal 2025?"}'
EndpointReturns
POST /askcited answer, sources, route, verification, trace ID
GET /tracesthe newest questions, one summary row each
GET /traces/{id}every span for one trace
GET /statusmodel, keys present (yes/no), A2A agent reachability
GET /health{"status":"ok"}

MCP server

Four read-only tools any MCP client can call, such as Claude Code or Claude Desktop. The server speaks stdio and is started by its client.

Start with calculate: it needs no keys or data. Every response carries a trace_id.

ToolWhat it does
calculateratio, pct_change, margin, cagr with named inputs
query_financialstext-to-SQL over the XBRL facts; returns SQL, rows, calculations
search_filingshybrid search; ranked passages with ticker, section, accession number
ask_finsightthe whole verified pipeline in one call (slower)
use it from Claude Code (once)
claude mcp add finsight -- uv --directory "$(pwd)" run python -m finsight.mcp_server
or try the tools in the MCP Inspector
npx @modelcontextprotocol/inspector uv run python -m finsight.mcp_server

A2A agents

Retrieval, facts and verification can run as separate services that publish an Agent Card. The API delegates to an agent only when its URL is set, and anything unset stays in-process.

Once a URL is set, /ask fails if that agent is not running, so start the workers first. Remove the variable to go back to single-process mode.

  • Live status loads from /status.
start each worker in its own terminal
uv run python -m finsight.agents retrieval   # :9101
uv run python -m finsight.agents facts       # :9102
uv run python -m finsight.agents verifier    # :9103
read an Agent Card
curl -s http://127.0.0.1:9101/.well-known/agent-card.json
point the API at the workers
FINSIGHT_A2A_RETRIEVAL_URL=http://127.0.0.1:9101 \
FINSIGHT_A2A_FACTS_URL=http://127.0.0.1:9102 \
FINSIGHT_A2A_VERIFIER_URL=http://127.0.0.1:9103 \
uv run uvicorn finsight.api.app:app --host 127.0.0.1 --port 8000

In the trace, every a2a.call span in [api] has a matching a2a.handle span in the worker that served it.

Command line

Retrieval plus a cited answer without the orchestrator, and a timeline viewer for traces. --retrieve-only prints just the ranked passages, which is useful for checking search quality.

cited answer from retrieval
uv run python -m finsight.retrieval.cli "export restrictions China" --ticker NVDA
passages only
uv run python -m finsight.retrieval.cli "export restrictions China" --ticker NVDA --retrieve-only
trace timeline
uv run python -m finsight.trace_cli --last
uv run python -m finsight.trace_cli <trace_id>

Tests and evaluations

The unit tests replace Pinecone, the language model and the network with fakes, so they need no keys and cost nothing. They cover the SQL guard, the verifier, the router, the full graph, tracing, MCP, A2A and the LangSmith export. CI runs the first two commands on every push.

Evaluations call Pinecone and Claude, so they cost money. They are not part of CI.

offline, free
uv run pytest
uv run ruff check . && uv run ruff format --check .
evaluations (paid)
uv run python -m finsight.evals.run --validate
uv run python -m finsight.evals.run --name baseline
uv run python -m finsight.evals.run --name e2e --e2e --verify on

Optional: LangSmith

Off by default. Each question appears as one finsight.ask run with a child per graph node, plus the model calls (with token usage), the Pinecone search and the SQL tool, all carrying the same finsight_trace_id as the local traces.

Unlike the local trace files, LangSmith receives content (prompts, filing passages, answers). Add the two hide flags to send only the structure. Restart the server after changing .env.

add to .env, then restart
LANGSMITH_TRACING=true
LANGSMITH_API_KEY=...        # your own key
LANGSMITH_PROJECT=finsight
# optional: send structure only
LANGSMITH_HIDE_INPUTS=true
LANGSMITH_HIDE_OUTPUTS=true
